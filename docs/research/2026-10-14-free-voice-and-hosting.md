# Medivaanii — free voice models and deployment proposal

Research date: 14 October 2026. This updates the earlier paid-provider recommendation in response to the user's zero-spend preference. The pilot remains English, Hindi, Spanish and Mandarin, focused on conversational understanding of the uploaded report. No models were downloaded, accounts created, API calls benchmarked, or services deployed during this research.

**Decision**

A prototype can avoid model/API fees by running open models on existing hardware. A small internet-accessible pilot can also target $0 service charges within published free allowances. Neither establishes unlimited, always-available free production service. Existing hardware, electricity, connectivity, engineering work, and any optional domain still have costs.

For this project, use a local stack as the private evaluation baseline and test a quota-limited hosted stack for external access. Keep paid APIs disabled and stop gracefully when free capacity is exhausted. The earlier ElevenLabs/GPT paid stack is now a comparison option, not the default implementation target.

**Free local model stack**

| Stage | Initial candidate | Why it fits | What must be measured |
| --- | --- | --- | --- |
| Listening | Multilingual Whisper `small` through `whisper.cpp` | Local recognition, MIT runtime, Apple Silicon acceleration | Hindi/English mixing, rural accents, Mandarin, Spanish, noise and medical numbers |
| Explanation | Qwen3.5-4B, quantized, text-only requests through a local runtime | Apache-2.0 model; broad multilingual coverage; no per-call fee | Four-language comprehension and faithfulness, memory and time to answer |
| Speaking | Kokoro-82M | Apache-2.0 weights; small model with English/Hindi/Spanish/Mandarin voices | Native pronunciation, medical units, intelligibility and voice preference |
| Conversation controls | Our existing Flutter/Python app plus speech detection and cancellation | No managed-agent fee; preserves the approved UI and source logic | Echo, interruptions, turn boundaries, reconnect and stale-answer cancellation |

The local machine inspected is an Apple M1 MacBook Air with 8 GB RAM. That is a useful prototype candidate, not a measured performance guarantee. The Ollama registry lists `qwen3.5:4b` at approximately 3.4 GB on disk; runtime memory additionally includes context/cache, speech models, the operating system and the app. Start with one active session, approximately 4K context, short answers, and no simultaneous Docling processing. Retrieve relevant report records instead of putting every PDF page into the prompt. Compare a smaller model only if memory requires it; a smaller model must pass the same answer checks rather than becoming an invisible quality downgrade. [Qwen model card](https://huggingface.co/Qwen/Qwen3.5-4B), [Ollama tags](https://registry.ollama.com/library/qwen3.5/tags).

Use multilingual Whisper weights, not `.en` variants. `whisper.cpp` documents Metal/Core ML support and approximately 852 MB memory for unquantized `small`; actual combined memory must be measured here. [Whisper model card](https://huggingface.co/openai/whisper-small), [runtime documentation](https://github.com/ggml-org/whisper.cpp).

Kokoro's native voice inventory covers all four pilot languages, but its publisher describes thin training/G2P coverage for some languages. Its Hindi and Mandarin catalogue quality estimates are weaker than its best English voices. Therefore, “free and supported” does not prove premium speech in every language. Audition it with native listeners before selecting voices. Keep speech assets/phonemizers cached so a local conversation does not accidentally call a cloud fallback. [Kokoro model card](https://huggingface.co/hexgrad/Kokoro-82M), [voice inventory and limitations](https://huggingface.co/hexgrad/Kokoro-82M/blob/main/VOICES.md).

Chatterbox Multilingual V3 is an alternative open model to audition if Kokoro's pronunciation fails: its official repository describes a 500M multilingual model, MIT licensing and support for the target languages. It requires a separate memory/speed check on this machine. Its lightweight Turbo/Nano variants are English-only, so they do not solve the complete four-language requirement. [Chatterbox repository](https://github.com/resemble-ai/chatterbox).

The local architecture can work without external AI services after dependencies, models, fonts and reviewed content are cached. The current app as a whole is not offline: its translation/TTS fallbacks call external services. A strict-local configuration must replace or disable those paths. For remote users, the Mac would need to remain awake and reachable through an authenticated service; a public frontend cannot connect to a different person's `localhost`. Do not expose the current unauthenticated development API as a public model server.

**Recommended $0 hosted-pilot candidate**

| Component | Candidate deployment | Published free allowance / constraint |
| --- | --- | --- |
| Frontend | Cloudflare Pages, built Flutter web assets | Static asset requests free; current compiled assets are below its 25 MiB per-file limit |
| Python extraction and report-answer API | Render Free web service | Sleeps after 15 minutes idle; approximately one-minute wake-up; local files are ephemeral; memory and CPU must be profiled |
| Identity and persistent report/session metadata | Supabase Free | 500 MB database, 1 GB file storage, 5 GB egress; inactivity pause; use access policies and private buckets |
| Listening | Cloudflare Workers AI `@cf/openai/whisper-large-v3-turbo` | Counts against the shared daily AI allowance; clip-based recognition initially |
| Explanation | Cloudflare Workers AI `@cf/qwen/qwen3-30b-a3b-fp8` | Same AI allowance; compact source-grounded context, application validation |
| Speaking | Azure Speech **F0**, standard neural voices | 0.5 million characters/month; select the explicit free resource tier, not a paid resource |

This is a proposed combination, not a verified deployment. It avoids putting large model weights on the free Python server: model inference happens on the hosted providers. Cloudflare Pages serves the UI; it does not run our current pdfplumber/Tesseract/Docling Python pipeline. Render's native extraction path needs a reproducible container and an actual memory/upload benchmark. If it fails the free hardware budget, keep extraction local for demonstrations or reassess hosting; do not claim arbitrary-report support by skipping extraction checks.

[Pages pricing](https://developers.cloudflare.com/pages/functions/pricing/), [Pages limits](https://developers.cloudflare.com/pages/platform/limits/), [Render Free constraints](https://render.com/docs/free), [Supabase pricing](https://supabase.com/pricing) support the hosting comparison. Local frontend inspection found the largest compiled asset at approximately 6.95 MiB. This only verifies asset size compatibility, not deployment success.

Cloudflare currently includes 10,000 AI Neurons/day; Free usage stops when the allowance is exceeded, while several frontier models require paid access. The selected models appear in the current catalogue/pricing without the listed paid-only restriction. Confirm account access before choosing them. Published rates are 46.63 Neurons per minute of Whisper Turbo input and, for the selected Qwen model, 4,625 per million input tokens plus 30,475 per million output tokens. An assumed session using two minutes of input speech, 30K total input tokens across turns and 2K output tokens is about 293 Neurons, excluding retries/other AI usage. The arithmetic is an estimate, not a capacity benchmark. [Workers AI pricing](https://developers.cloudflare.com/workers-ai/platform/pricing/), [Whisper Turbo endpoint](https://developers.cloudflare.com/workers-ai/models/whisper-large-v3-turbo/), [Qwen endpoint](https://developers.cloudflare.com/workers-ai/models/qwen3-30b-a3b-fp8/).

Azure's explicit Speech F0 tier includes 500,000 neural TTS characters/month and five hours/month of realtime recognition. Its separate Voice Live agent service is not included in F0; we would build the conversation ourselves. F0 TTS permits 20 requests/minute and realtime recognition has a one-concurrent-request limit. The main hosted proposal uses Cloudflare for clip recognition, so it does not depend on Azure's five-hour recognition quota. Verify resource/voice availability, billing character rules and regional access in the account. [Azure Speech pricing](https://azure.microsoft.com/en-us/pricing/details/speech/), [quotas](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/speech-services-quotas-and-limits).

Azure documents neural voices for all four languages. Candidates to audition include Hindi `hi-IN-SwaraNeural`, Spanish `es-MX-DaliaNeural`, Mandarin `zh-CN-XiaoxiaoNeural`, and an appropriate English voice. Choose standard neural voices covered by the selected tier; do not assume Neural HD/custom voices have the same free entitlement. [Language/voice support](https://learn.microsoft.com/en-us/azure/ai-services/speech-service/language-support?tabs=tts).

For an initial pilot, provisionally cap access at five sessions/day and 100 sessions/month, with a conservative per-session spoken-character budget and short answers. For illustration, 3,000 billable characters per session across 100 sessions is 300,000/month, below the published 500,000 allowance. Real usage includes retries, speech normalization and applicable SSML character billing; reconcile with provider usage. A cap is a product/engineering choice, not a promise of available provider capacity. Stop before allowances are exhausted and show a useful retry/text option. Do not split accounts, rotate keys, or use keep-alive traffic to circumvent free-tier restrictions.

Groq is an alternative to compare for hosted recognition and reasoning, rather than a second provider invoked on every turn. Its current free table lists `qwen/qwen3.8-27b` at 30 requests/minute, 8K tokens/minute and 200K tokens/day, and Whisper models at 28,800 audio seconds/day. These limits are organization-wide and actual account exceptions are documented. A 32K-token session would use roughly one sixth of a 200K daily allowance before other traffic. Groq's TTS catalogue does not supply the complete four-language voice solution, so Azure/local speech would still be needed. [Groq limits](https://console.groq.com/docs/rate-limits), [supported models](https://console.groq.com/docs/models).

**Where Vercel and Hugging Face fit**

Vercel can host the frontend and light API calls for a qualifying personal prototype. Hobby is explicitly restricted to personal, non-commercial use, so it is not the proposed long-term free host for a commercial Medivaanii product. Its function memory/duration/upload constraints also differ from a persistent model server: the current app accepts up to 10 MB uploads, whereas function payloads are limited to 4.5 MB. A direct object-storage upload plus separate processing would be required. Current large-function beta supports bigger packages, so the obsolete statement “Python can never exceed 500 MB” is not the reason to reject it; runtime fit, lifecycle, uploads and commercial terms are the relevant reasons. [Hobby plan](https://vercel.com/docs/plans/hobby), [function limits](https://vercel.com/docs/functions/limitations), [large-function update](https://vercel.com/changelog/vercel-functions-can-now-be-up-to-5-gb-in-package-size-7yAwSyCig0IQDXUIDistvS/eadf06d6c3).

Current Hugging Face documentation says Static Spaces are free; creating CPU Gradio/Docker compute requires a paid plan even though CPU Basic has no hourly charge. Eligible free personal accounts in good standing can host up to two ZeroGPU Gradio Spaces, but free visitors get five minutes of GPU time/day and queues apply. That is useful for public synthetic demos or model auditions, not guaranteed continuous low-latency voice service. Do not rely on older advice that anyone can create an unlimited free CPU model server. [Spaces overview](https://huggingface.co/docs/hub/spaces-overview), [ZeroGPU quotas](https://huggingface.co/docs/hub/spaces-zerogpu).

Render Free is a backend candidate, not a free GPU service. Sleeping/restarting deletes local SQLite/uploads, and its free Postgres expires after 30 days. Store persistent records outside the runtime and make job status resumable or explicitly failed after a restart. Published bandwidth/build allowances must also be monitored; zero-spend depends on staying within all limits, not just AI usage.

**Free offers we should not confuse with a durable product**

Gemini 3.8 Live has a documented free quota and can be useful for synthetic conversational demos. For unpaid services in this user's region, Google's terms say not to submit sensitive/confidential/personal information and allow use of inputs/outputs to improve products, including human review. Therefore it is not the proposed free path for actual private patient reports. Linking a billing account changes applicable treatment, but that is a different account/billing configuration requiring separate verification. [Gemini pricing](https://ai.google.dev/gemini-api/docs/pricing), [unpaid-service terms](https://ai.google.dev/gemini-api/terms), [account-specific limits](https://ai.google.dev/gemini-api/docs/rate-limits).

Trial/startup credits and grants may help later but are not guaranteed recurring free service. Hugging Face Inference Providers' small starter credits are not unlimited model hosting. Public model demo endpoints are not an authorized, dependable production backend. Existing unofficial Edge TTS/Google Translate fallbacks should not be the production plan merely because they currently need no key. Browser-installed voices can provide a last-resort option, but language availability and audible quality vary by device.

**What remains essential in either free architecture**

The agent must use the complete authorized report inventory, current revision, eligible source fields and reviewed multilingual educational content. Each answer retrieves relevant records, produces a bounded structured answer, verifies values/units/source IDs and coverage, then releases approved text to speech. Numeric facts come from deterministic source rendering; a free language model does not get to replace missing data with guesses. Keep the original PDF highlight and neutral body explanations synchronized with the spoken topic.

Local models should also handle translation for a strict-local profile, with language-specific numeral/unit pronunciation and native-language limitation messages. The existing English-only question matcher cannot become a fluent four-language agent merely by adding microphone input. Every candidate needs multilingual conversation and emitted-audio testing before it is called usable.

Preserve the premium Medivaanii panel, restrained motion, large controls, captions, interruption, repeat/slower/simpler actions, and clear source cards. Start with short recorded turns/push-to-talk; add hands-free turn detection after the model/latency checks. A polite prerecorded acknowledgement must not be counted as the latency of the substantive report answer. Do not require rural users to download several gigabytes of models onto their phones.

The free hosted backend should process PDFs/photos sequentially, with explicit upload/page bounds and measured memory limits. Keep Docling available locally but disable its heavy worker on the smallest cloud instance unless an actual benchmark proves fit. Unresolved layouts stay partial/blocked; voice can explain the limitation and guide source review. Supporting arbitrary prescriptions, radiology, discharge reports, scans and handwriting remains separate extraction work.

Add identity, server-owned immutable report snapshots, revision invalidation, private storage access rules and deletion. Store provider keys only on the server; speech/session tokens must be short-lived and scoped. Do not retain raw audio by default or print patient content in logs. Free hosting or “not used for training” is not a medical-data compliance guarantee. Review the relevant vendor data settings/terms before a private hosted pilot. Cloudflare says it does not use Workers AI content for training/service improvement without explicit consent; Groq describes reliability/abuse retention exceptions and configurable controls. [Cloudflare data use](https://developers.cloudflare.com/workers-ai/platform/data-usage/), [Groq data controls](https://console.groq.com/docs/your-data).

**Next plan, without spending**

1. Compare local candidates using anonymous recordings and synthetic reports in the four languages. Measure source-faithfulness, spoken decimals/units, native-listener comprehension, response timing, interruptions and peak combined memory on the M1. Do not download/install or run private/provider tests until implementation is requested.
2. Build one provider-neutral conversation service with strict `local_only` and `free_quota` configurations. Keep the shared source/answer contract from the earlier plan. Disable all paid fallbacks. Use cached reviewed content for explanations and explicit unsupported-language errors.
3. Validate hosted account eligibility and actual quotas, then benchmark the lightweight Python extractor within free-instance limits. Move in-memory jobs and SQLite history to durable authorized storage before a hosted deployment. Native extraction, OCR memory, photo upload and cold-start recovery must pass.
4. Deploy the frontend and selected backend/model route only after those checks. Begin with synthetic reports, then a restricted opt-in pilot with reviewed data handling. Enforce usage counters, idempotent retries, maximum input/output budgets, monthly speech/bandwidth caps and clear exhausted-quota behavior.
5. Decide which route to retain from evidence. If free speech/comprehension/hosting fails, report the failed requirement and use the local route or reduce pilot scope. Do not claim equivalent quality to the paid stack, silently send data to unpaid Gemini, automatically enable paid services, or weaken extraction validation to meet the budget.

The recommended outcome is a private no-API-fee local prototype plus a small, explicitly limited $0 hosted pilot if all account, performance and privacy gates pass. Free website hosting alone does not solve model inference, PDF processing, persistent report context or deployment reliability.
